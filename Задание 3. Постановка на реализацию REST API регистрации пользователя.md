
## 1. Цель доработки

Необходимо реализовать REST API метод для регистрации нового пользователя в системе Book Store.

Метод должен вызываться фронтендом при нажатии пользователем кнопки `Register` на форме регистрации.

В рамках метода бэк-сервис должен:

1. Принять данные пользователя из формы регистрации.
2. Проверить корректность переданных данных.
3. Проверить прохождение reCaptcha.
4. Проверить, что пользователь с таким логином ещё не зарегистрирован.
5. Создать нового пользователя в базе данных.
6. Вернуть фронтенду результат регистрации.

## 2. Экран регистрации

На форме регистрации пользователь заполняет следующие поля:

1. `First Name` — имя пользователя.
2. `Last Name` — фамилия пользователя.
3. `UserName` — логин пользователя.
4. `Password` — пароль пользователя.
5. `reCaptcha` — подтверждение, что пользователь не является роботом.

После заполнения формы пользователь нажимает кнопку `Register`.

## 3. REST API метод

HTTP метод: `POST`

URL: `/api/v1/users/register`

Назначение метода: регистрация нового пользователя.

Content-Type: `application/json`

## 4. Входные параметры

|Параметр|Тип|Обязательный|Описание|Ограничения|
|---|---|---|---|---|
|`firstName`|string|Да|Имя пользователя|Не должно быть пустым. Максимальная длина — 50 символов|
|`lastName`|string|Да|Фамилия пользователя|Не должно быть пустым. Максимальная длина — 50 символов|
|`userName`|string|Да|Логин пользователя|Не должен быть пустым. Максимальная длина — 50 символов. Должен быть уникальным|
|`password`|string|Да|Пароль пользователя|Минимум 8 символов. Должен содержать цифру, заглавную букву, строчную букву и специальный символ|
|`recaptchaToken`|string|Да|Токен проверки reCaptcha|Должен быть передан после прохождения reCaptcha на фронтенде|

## 5. Пример запроса

```
POST /api/v1/users/register
Content-Type: application/json
```

```
{
  "firstName": "Ivan",
  "lastName": "Ivanov",
  "userName": "ivan",
  "password": "Password1!",
  "recaptchaToken": "03AFcWeA..."
}
```

## 6. Успешный ответ

HTTP статус: `201 Created`

Условие: пользователь успешно создан в базе данных.

|   |   |   |   |
|---|---|---|---|
|Параметр|Тип|Обязательный|Описание|
|`userId`|integer|Да|Идентификатор созданного пользователя|
|`userName`|string|Да|Логин созданного пользователя|
|`message`|string|Да|Сообщение об успешной регистрации|

Пример успешного ответа:

```
{
  "userId": 12345,
  "userName": "ivan",
  "message": "User Register Successfully"
}
```

## 7. Ответ с ошибкой

|   |   |   |   |
|---|---|---|---|
|Параметр|Тип|Обязательный|Описание|
|`errorCode`|string|Да|Внутренний код ошибки|
|`message`|string|Да|Текст ошибки для отображения на фронтенде|
|`details`|array|Нет|Детализация ошибок по конкретным полям|

## 8. Возможные ошибки

|   |   |   |   |
|---|---|---|---|
|HTTP статус|Код ошибки|Сообщение|Условие возникновения|
|`400 Bad Request`|`VALIDATION_ERROR`|`Validation error`|Не заполнено одно или несколько обязательных полей|
|`400 Bad Request`|`INVALID_PASSWORD`|`Password must have at least one non alphanumeric character, one digit ('0'-'9'), one uppercase ('A'-'Z'), one lowercase ('a'-'z'), one special character and Password must be eight characters or longer.`|Пароль не соответствует требованиям|
|`400 Bad Request`|`RECAPTCHA_REQUIRED`|`Please verify reCaptcha to register!`|Не передан токен reCaptcha|
|`400 Bad Request`|`RECAPTCHA_FAILED`|`Please verify reCaptcha to register!`|Проверка reCaptcha не пройдена|
|`409 Conflict`|`USER_EXISTS`|`User exists!`|Пользователь с таким `userName` уже существует|
|`500 Internal Server Error`|`INTERNAL_ERROR`|`Internal server error`|Непредвиденная ошибка на стороне сервера|

## 9. Примеры ответов с ошибкой

### 9.1. Ошибка проверки пароля

HTTP статус: `400 Bad Request`

```
{
  "errorCode": "INVALID_PASSWORD",
  "message": "Password must have at least one non alphanumeric character, one digit ('0'-'9'), one uppercase ('A'-'Z'), one lowercase ('a'-'z'), one special character and Password must be eight characters or longer."
}
```

### 9.2. Пользователь уже существует

HTTP статус: `409 Conflict`

```
{
  "errorCode": "USER_EXISTS",
  "message": "User exists!"
}
```

### 9.3. reCaptcha не пройдена

HTTP статус: `400 Bad Request`

```
{
  "errorCode": "RECAPTCHA_REQUIRED",
  "message": "Please verify reCaptcha to register!"
}
```

### 9.4. Ошибка обязательных полей

HTTP статус: `400 Bad Request`

```
{
  "errorCode": "VALIDATION_ERROR",
  "message": "Validation error",
  "details": [
    {
      "field": "firstName",

    },

    }
  ]
}
```

## 10. Алгоритм работы бэк-сервиса

1. Бэк-сервис получает запрос `POST /api/v1/users/register`.
2. Сервис получает из тела запроса следующие данные:
    - `firstName`;
    - `lastName`;
    - `userName`;
    - `password`;
    - `recaptchaToken`.
3. Сервис проверяет, что тело запроса передано в формате JSON.
4. Сервис проверяет наличие обязательных полей:
    - `firstName`;
    - `lastName`;
    - `userName`;
    - `password`;
    - `recaptchaToken`.
5. Если одно или несколько обязательных полей не переданы, сервис возвращает ошибку `400 Bad Request`.
6. Сервис удаляет лишние пробелы в начале и конце значений:
    - `firstName`;
    - `lastName`;
    - `userName`.
7. Сервис проверяет длину текстовых полей:
    - `firstName` — не более 50 символов;
    - `lastName` — не более 50 символов;
    - `userName` — не более 50 символов.
8. Если одно из полей превышает допустимую длину, сервис возвращает ошибку `400 Bad Request`.
9. Сервис проверяет пароль на соответствие требованиям:
    - длина не менее 8 символов;
    - есть хотя бы одна цифра;
    - есть хотя бы одна заглавная буква;
    - есть хотя бы одна строчная буква;
    - есть хотя бы один специальный символ.
10. Если пароль не соответствует требованиям, сервис возвращает ошибку `400 Bad Request` с кодом `INVALID_PASSWORD`.
11. Сервис проверяет наличие `recaptchaToken`.
12. Если `recaptchaToken` не передан, сервис возвращает ошибку `400 Bad Request` с кодом `RECAPTCHA_REQUIRED`.
13. Сервис отправляет `recaptchaToken` на проверку в сервис reCaptcha.
14. Если reCaptcha не пройдена, сервис возвращает ошибку `400 Bad Request` с кодом `RECAPTCHA_FAILED`.
15. Сервис выполняет поиск пользователя в базе данных по полю `userName`.
16. Если пользователь с таким `userName` уже существует, сервис возвращает ошибку `409 Conflict` с кодом `USER_EXISTS`.
17. Если пользователь с таким `userName` не найден, сервис хэширует пароль.
18. Сервис создаёт нового пользователя в базе данных.
19. В базе данных сохраняются:

- имя пользователя;
- фамилия пользователя;
- логин пользователя;
- хэш пароля.

20. Пароль в открытом виде в базе данных не сохраняется.
21. Если пользователь успешно создан, сервис возвращает ответ `201 Created`.
22. Если при выполнении операции произошла непредвиденная ошибка, сервис возвращает `500 Internal Server Error`.

## 11. Требования к безопасности

1. Пароль пользователя не должен сохраняться в базе данных в открытом виде.
2. Перед сохранением пароль должен быть захэширован.
3. В ответе API не должен возвращаться пароль или хэш пароля.
4. Проверка reCaptcha должна выполняться на стороне бэк-сервиса.
5. Ошибки сервера не должны раскрывать технические детали реализации.
