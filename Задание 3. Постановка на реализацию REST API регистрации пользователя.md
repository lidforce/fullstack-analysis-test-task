
## 1. Цель доработки

Необходимо реализовать REST API метод для регистрации нового пользователя в системе Book Store.

Метод вызывается фронтендом после нажатия кнопки `Register` на форме регистрации.

Бэк-сервис должен принять данные из формы, проверить их корректность, проверить reCaptcha, убедиться, что пользователь с таким логином ещё не существует, создать пользователя в базе данных и вернуть результат регистрации.

## 2. Данные формы регистрации

На экране регистрации пользователь заполняет следующие поля:

|Поле на форме|Описание|
|---|---|
|`First Name`|Имя пользователя|
|`Last Name`|Фамилия пользователя|
|`UserName`|Логин пользователя|
|`Password`|Пароль пользователя|
|`reCaptcha`|Проверка, что пользователь не является роботом|

## 3. REST API метод

|Параметр|Значение|
|---|---|
|HTTP метод|`POST`|
|URL|`/api/v1/users/register`|
|Content-Type|`application/json`|
|Назначение|Регистрация нового пользователя|

## 4. Входные параметры

|Параметр|Тип|Обязательный|Описание|Ограничения|
|---|---|---|---|---|
|`firstName`|string|Да|Имя пользователя|Не пустое значение, максимум 50 символов|
|`lastName`|string|Да|Фамилия пользователя|Не пустое значение, максимум 50 символов|
|`userName`|string|Да|Логин пользователя|Не пустое значение, максимум 50 символов, должен быть уникальным|
|`password`|string|Да|Пароль пользователя|Минимум 8 символов, минимум одна цифра, одна заглавная буква, одна строчная буква и один специальный символ|
|`recaptchaToken`|string|Да|Токен reCaptcha, полученный на фронтенде|Должен быть передан и успешно проверен на стороне бэк-сервиса|

## 5. Пример запроса

```http
POST /api/v1/users/register
Content-Type: application/json
```

```json
{
  "firstName": "Ivan",
  "lastName": "Ivanov",
  "userName": "ivan",
  "password": "Password1!",
  "recaptchaToken": "03AFcWeA..."
}
```

## 6. Успешный ответ

HTTP статус: `201 Created`

Условие: пользователь успешно создан в базе данных.

|Параметр|Тип|Обязательный|Описание|
|---|---|---|---|
|`userId`|integer|Да|Идентификатор созданного пользователя|
|`userName`|string|Да|Логин созданного пользователя|
|`message`|string|Да|Сообщение об успешной регистрации|

Пример ответа:

```json
{
  "userId": 12345,
  "userName": "ivan",
  "message": "User Register Successfully"
}
```

## 7. Формат ответа с ошибкой

|Параметр|Тип|Обязательный|Описание|
|---|---|---|---|
|`errorCode`|string|Да|Код ошибки|
|`message`|string|Да|Текст ошибки|
|`details`|array|Нет|Список ошибок по отдельным полям|

## 8. Возможные ошибки

|Условие|HTTP статус|Код ошибки|Сообщение|
|---|---|---|---|
|Тело запроса отсутствует или передано не в формате JSON|`400 Bad Request`|`INVALID_REQUEST`|`Invalid request body`|
|Не заполнено одно или несколько обязательных полей|`400 Bad Request`|`VALIDATION_ERROR`|`Validation error`|
|Значение одного из текстовых полей превышает допустимую длину|`400 Bad Request`|`VALIDATION_ERROR`|`Validation error`|
|Пароль не соответствует требованиям безопасности|`400 Bad Request`|`INVALID_PASSWORD`|`Password must have at least one non alphanumeric character, one digit ('0'-'9'), one uppercase ('A'-'Z'), one lowercase ('a'-'z'), one special character and Password must be eight characters or longer.`|
|Не передан токен reCaptcha|`400 Bad Request`|`RECAPTCHA_REQUIRED`|`Please verify reCaptcha to register!`|
|Проверка reCaptcha не пройдена|`400 Bad Request`|`RECAPTCHA_FAILED`|`Please verify reCaptcha to register!`|
|Пользователь с таким `userName` уже существует|`409 Conflict`|`USER_EXISTS`|`User exists!`|
|Произошла непредвиденная ошибка на стороне сервера|`500 Internal Server Error`|`INTERNAL_ERROR`|`Internal server error`|

## 9. Примеры ответов с ошибкой

### 9.1. Ошибка проверки пароля

HTTP статус: `400 Bad Request`

```json
{
  "errorCode": "INVALID_PASSWORD",
  "message": "Password must have at least one non alphanumeric character, one digit ('0'-'9'), one uppercase ('A'-'Z'), one lowercase ('a'-'z'), one special character and Password must be eight characters or longer."
}
```

### 9.2. Пользователь уже существует

HTTP статус: `409 Conflict`

```json
{
  "errorCode": "USER_EXISTS",
  "message": "User exists!"
}
```

### 9.3. reCaptcha не пройдена

HTTP статус: `400 Bad Request`

```json
{
  "errorCode": "RECAPTCHA_FAILED",
  "message": "Please verify reCaptcha to register!"
}
```

### 9.4. Не заполнены обязательные поля

HTTP статус: `400 Bad Request`

```json
{
  "errorCode": "VALIDATION_ERROR",
  "message": "Validation error",
  "details": [
    {
      "field": "firstName",
      "message": "First Name is required"
    },
    {
      "field": "password",
      "message": "Password is required"
    }
  ]
}
```

## 10. Алгоритм работы бэк-сервиса

|Шаг|Действие|Если проверка не пройдена|Если проверка пройдена|
|---|---|---|---|
|1|Получить запрос `POST /api/v1/users/register`|Вернуть `400 Bad Request`, если тело запроса отсутствует или не является JSON|Перейти к проверке входных параметров|
|2|Проверить наличие обязательных полей: `firstName`, `lastName`, `userName`, `password`, `recaptchaToken`|Вернуть `400 Bad Request` с кодом `VALIDATION_ERROR`|Перейти к нормализации данных|
|3|Удалить лишние пробелы в начале и конце значений `firstName`, `lastName`, `userName`|—|Перейти к проверке длины полей|
|4|Проверить длину `firstName`, `lastName`, `userName`|Вернуть `400 Bad Request` с кодом `VALIDATION_ERROR`, если значение превышает 50 символов|Перейти к проверке пароля|
|5|Проверить пароль: минимум 8 символов, есть цифра, заглавная буква, строчная буква и специальный символ|Вернуть `400 Bad Request` с кодом `INVALID_PASSWORD`|Перейти к проверке reCaptcha|
|6|Проверить `recaptchaToken` через сервис reCaptcha|Вернуть `400 Bad Request` с кодом `RECAPTCHA_FAILED`, если проверка не пройдена|Перейти к проверке пользователя в БД|
|7|Найти пользователя в БД по `userName`|Вернуть `409 Conflict` с кодом `USER_EXISTS`, если пользователь уже существует|Перейти к созданию пользователя|
|8|Захэшировать пароль|Вернуть `500 Internal Server Error`, если возникла техническая ошибка|Перейти к сохранению пользователя|
|9|Создать пользователя в базе данных|Вернуть `500 Internal Server Error`, если возникла ошибка при сохранении|Вернуть `201 Created`|

При создании пользователя в базе данных сохраняются:

- имя пользователя;
    
- фамилия пользователя;
    
- логин пользователя;
    
- хэш пароля.
    

Пароль в открытом виде сохранять нельзя.

## 11. Требования к безопасности

1. Пароль пользователя не должен сохраняться в базе данных в открытом виде.
    
2. Перед сохранением пароль должен быть захэширован.
    
3. В ответе API не должен возвращаться пароль или хэш пароля.
    
4. Проверка reCaptcha должна выполняться на стороне бэк-сервиса.
    
5. Ошибки сервера не должны раскрывать технические детали реализации.
